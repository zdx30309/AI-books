# 通用长篇操作手册

> 面向使用者（不是开发者）。目标：**任何时候打开工作区，都知道下一步点哪一个按钮，以及这一步花不花钱。**
> 指令原文、验收门、字数与 Word 规则写在 ```docs/GENERAL_LONGFORM_V02.md``` 和 ```docs/GENERAL_LONGFORM.md```，本文件只讲怎么操作。

## 0. 一句话理解它

通用长篇是「**点一次、跑一步**」的十万字生产车间：

- 每个阶段跑完就**停下来等你**，不会自己往下跑（这是严格串行 + 每章验收的设计，不是坏了）。
- 停下来时任务列表可能显示「已暂停」——那是正常的等待状态。
- **已验收的正文和状态永远由系统哈希校验并锁定**；草稿、修复稿都不会写进成果。

停下来时一定是下面之一：

| 阶段（工作区显示的徽章） | 意思 | 通常的下一步 |
| --- | --- | --- |
| 准备策划 | 还没大纲 | 研究并生成待确认大纲（或恢复上次操作） |
| 等待确认大纲 | 五组包装 + 12—15 章大纲已生成 | 选方案 → 确认选中包装与大纲 |
| 等待下一章操作 | 已验收 N 章 | 研究并写作第 N 章（有候选稿时按钮变成「继续完成第 N 章」） |
| 等待全书终审 | 全部章节已验收 | 全书终审与合稿 Word |
| 有待处理项 | 有东西被拦下了 | 看工作区顶部的「下一步」面板 |
| 断点已保存 | 你点过暂停 | 恢复上次操作 |
| 当前章写作中 | 正在跑 | 什么都别点，等它跑完 |
| 全书已验收 | 完成 | 去「文件」页下载 |

## 1. 从一条视频链接到一本书（完整操作流程）

1. **建任务**：书架 → 新建任务 → 分类选「通用长篇」。
   - 「参考视频链接（可选）」填 B 站/抖音等链接：系统会先用现有的短篇解析链路提取逐字稿，再进入策划。
   - 也可以什么都不填：通用长篇按九领域自主选题；或在「选题要求或视频逐字稿」里写清楚方向。
   - 已经有旧稿/旧大纲时，勾选「先创建工作区」，建完任务去「材料」页上传，再点「识别材料并继续当前阶段」。
2. **点「研究并生成待确认大纲」**：跑「参考机制抽象 →（有素材时）素材摘要 → 真实联网检索 → 逐页证据核验 → 五组包装与十万字大纲」。
3. **在「规划」页确认大纲**：对比五组书名/简介，选一个 → 点「确认选中包装与大纲」。确认只产出确认版大纲 Word，**不会顺手写第一章**。
4. **逐章推进**：点「研究并写作第 N 章」。系统会：本章检索 → 分节起草 → 一润 → 二润 → 状态抽取 → 计划实绩对比 → 验收门 → 必要时一次局部修复 + 复验 → 保存验收状态 → 导出两份 Word。**一次只做一章。**
5. **每章结束后**：在「文件」页下载这一章的**两份 Word**（正文 + 来源与编辑记录），或直接在「章节」页读正文。
6. **改稿**：某一章不满意 →「章节」页选章号 → 写清楚修改范围 →「修订、复验并导出两份 Word」。修订同样要重新过验收门，不允许绕过。
7. **全书终审与合稿**：全部章节验收后点「全书终审与合稿 Word」。系统核对有效正文总字数（必须落在 100000—110000）、章节、来源与终审问题，再产出全书 Word 和 ```manuscript.md```。

## 2. 「下一步」面板

工作区顶部固定显示一个**下一步**面板，内容由后端根据持久化状态算出，**不发任何模型调用**：

- **一句话现状**：为什么停在这里。
- **一个主按钮**：现在最该点的那一个（带理由）。
- **若干备选**：换方向时才用（例如「重新联网检索」和「用已付费断点继续」）。
- **费用标注**：每个动作都会写明「复用断点，不重复扣费」还是「会产生一次新的联网检索」。
- **不要点的东西**：明确列出「现在点它只会被同一条规则再拦一次」的按钮（例如字数不达标时，合稿按钮会被直接置灰并写上原因）。

命令行也能看到同一句话（只读数据库和状态文件，不改任务、不花钱）：

```powershell
python scripts\general_longform_doctor.py            # 全部通用长篇项目
python scripts\general_longform_doctor.py --task <任务id>
python scripts\general_longform_doctor.py --json
```

## 3. 卡住了对照表

| 你看到 | 系统在说什么 | 你点什么 | 花不花钱 |
| --- | --- | --- | --- |
| 首版大纲被拦：书名 10—18 字、简介 200—300 字不达标 | 「大纲候选已保留」面板 + 具体哪一条不合格 | **按校验结果修复候选大纲（不重新检索）** | 只 1 次大纲局部修订；检索证据复用 |
| 来源摘要在核验时全被排除 | 已读取 N 个页面 + 被排除条目的原因 | **恢复上次操作** | 只重跑来源抽象，**不重新联网**；每点一次最多多 1 次抽象调用 |
| 章节没写足 | 「第 N 章 XX 仍未写足，部分稿已保存」 | **继续完成第 N 章** | 从断点续写，已写小节不重写 |
| 本章验收有高/严重问题 | 验收问题清单 | 下一步面板里的「按验收问题修订第 N 章」（修改要求已按报告填好） | 1 次局部修复 + 重新验收 |
| 合稿被字数拦下 | 「全书真实正文为 X 字」 | 面板给出的「修订第 N 章并扩充/压缩约 M 字」（已算好字数、已填好要求） | 1 次章节修订 + 重新验收 |
| 终审有高/严重问题 | 终审报告逐条问题 | 面板给出的「按终审报告修订第 N 章」 | 1 次章节修订 + 重新验收 + 再合稿 |
| 交付待定（上次调用没拿到响应 ID） | 「上次模型调用交付状态待核对」 | 先看「日志」页 → 勾选「我已核对交付待定调用」→ **恢复上次操作** | 有响应 ID 时取回原响应；否则按你的勾选发新请求 |
| 上一章两份 Word 没齐 | 「第 N 章的配套 Word 还没补齐」 | **恢复上次操作** | 只补导出，不重新生成正文 |
| 项目固定 prompt 哈希不一致 | 「项目 prompt 源文件哈希与其固定版本不一致」 | 环境问题：`python scripts/import_general_longform_prompt.py` 恢复对应版本后重开工作区 | 不涉及生成 |

## 4. 什么情况才是「真的不干活」

只有三种，而且都有自愈或明确处置：

1. **处理中心跳不动**：`STALE_PROCESSING_REQUEUE_SECONDS`（默认 900 秒）后看门狗自动重排（每 120 秒检查一次）。心跳新鲜时**不要重复点按钮**，重复提交会被 409 拒绝。
2. **任务失败**：`FAILED_TASK_AUTO_RECOVERY_*`（默认 600 秒后重试，最多 24 次）自动重试；反复失败看错误信息，多半是额度/密钥/来源问题。
3. **人工闸门**：任务配置里有 `generation_hold` / `paid_call_delivery_uncertain` / `paid_call_manual_resume_required` / `pause_requested` 时，看门狗**主动跳过**，必须人工处理。

连「排队中」都不动，说明 worker/beat 没在消费队列：

```powershell
docker compose ps                     # backend / worker / maintenance / beat 都要 Up
docker compose logs --tail=100 worker
docker compose logs --tail=100 beat
```

## 5. 费用：哪些是免费的，哪些会新花钱

| 动作 | 是否复用已付费结果 |
| --- | --- |
| 刷新状态、打开工作区、看「下一步」面板 | 免费，纯读状态 |
| 恢复上次操作 | **复用**同一请求 id 下的已完成调用（参考抽象、素材摘要、联网检索、已读页面全都复用），只补未完成的那一步 |
| 按校验结果修复候选大纲 | 复用检索证据，只新增 1 次大纲局部修订 |
| 继续完成第 N 章 | 已写小节不重写，只补未完成的小节 |
| 研究并生成待确认大纲 | **新的联网检索** + 包装大纲生成 |
| 按我的要求修订大纲 | **新的联网检索** + 大纲修订 |
| 研究并写作第 N 章 | 新的联网检索 + 分节起草 + 一润 + 二润 + 验收 |
| 修订第 N 章 | 局部修复 + 重新验收 |
| 全书终审与合稿 | 终审 + 导出 |

「日志」页保留最近 200 次调用的动作、模型、状态、估算费用和错误；没有配置费率的显示「未配置费率 / 待核算」，不会假装是 0 元。

## 6. 常见问题

**Q：为什么写完一章就停了？能不能让它自己把 12 章跑完？**
A：这是刻意的：每章都必须过验收门，而且你要能随时停。目前没有「自动连跑」开关；需要无人值守时按 `next_chapter` 循环调用工作区接口（每次仍走同一套验收与断点，不会跳过任何一章）。

**Q：我把「已暂停」理解成出错了吗？**
A：不是。通用长篇每个阶段结束后就是这种等待状态；看「下一步」面板或运行 `general_longform_doctor.py` 就知道该点哪。

**Q：能直接改正文吗？**
A：不能，也不需要。已验收正文有哈希校验，直接改会被判为不一致并阻断；改稿一律走「指定章局部修订」，改完重新过验收门。

**Q：书名/简介确认后发现不合适？**
A：还没开始正文时可以重新确认或走大纲局部修订；一旦有验收正文，包装（书名/简介）保持固定，避免前后不一致。

**Q：想中途换模型 / 省钱？**
A：模型与 tier 由环境变量控制（见 `docs/GENERAL_LONGFORM.md` 与 `.env.example`），和工作区操作无关；通用长篇每个节点都按已配置费率记账。改完之后加一次 `docker compose restart worker beat`。

**Q：怎么看每个节点读了哪些页面、花了多少钱？**
A：「研究」页看已核验来源与读取范围；「日志」页看调用、模型、状态与估算费用；`backend/output/task_<id>/general_longform/` 里是断点、候选稿、验收记录与导出。

## 7. 不要做的事

- 不要在运行中重复点同一个按钮（同一本书严格串行，会 409）。
- 不要用旧通用入口「重新生成」或直接改分类/书名来绕过版本与验收。
- 不要把原始参考书文本塞进正文生成；参考只用于摄取与抽象（系统层面已强制）。
- 不要为了「跑快点」跳过确认大纲或跳过某章——跳章会被前文完整性检查挡住。
