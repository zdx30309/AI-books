# 编辑交付 0.5 版

按2026年10月13日编辑反馈，在现有视频成稿流程之后新增独立交付层，不重写主笔、一润、二润或格式化流程。只对上线时间之后的视频/参考文章短篇启用；历史书、古文、公版长篇、通用长篇、漫画和Epic canon不切换。

流程：完整视频文案/参考原稿与降AI前完整成稿进行结构框架与素材双维相似度审查 → 朱雀v1默认中文自媒体接口降AI（不传大雅工作模式，不做段落增强） → DeepSeek按优化版双稿指令进行局部纠错 → 交付两份Word。

最终ZIP只包含相似度审查报告和带真实修订的纠错Word。纠错Excel、原稿、降AI文本、模型原始响应、使用量和断点留在服务器供核对，不作为额外最终文件。严重纠错记录仍标红并统计，遵循既有AI_OR_SEVERE_BLOCKS_DELIVERY配置；不改Epic严重项阻断规则。

相似度报告审查对象是降AI前完整成稿，不是最终纠错稿；报告名称、JSON及源/稿hash明确绑定这个阶段。报告高危不自动重写，不等同发布许可；编辑需按报告优先改骨架，修改后应重新审查。未接入人工率或AI特征检测，不承诺人工率>50%或AI特征0%。

评分严格使用S分项40/30/30、M分项30/25/20/25、综合60/40；50%及以上高危，S≥70%始终提示改骨架。模型提供完整语义依据，程序核验原稿/新稿摘录并从表格计数复算，字面层使用autojunk=False及6/8/10/15/20-gram。没有完整两稿、无效依据或响应截断时暂停，不伪造检测结果。原始指令中“结构≥70%不得判安全”与综合硬阈值有冲突，采用其明确的综合阈值和结构兜底提示，不暗改公式。

提示词从两份Word正文及全部表格按XML顺序提取，分别保存到backend/app/prompts/editor_v05/。相似度指令5个表格均已提取，无文本框/图片；纠错指令无表格、文本框或图片。独立transport文件只定义JSON交付形式，模型不负责写文件；完整指令不删减。输入视频文案为纯文本，不宣称DOCX文字提取率100%。

开关：EDITOR_V05_ENABLED=True、EDITOR_V05_START_AT为UTC上线边界、EDITOR_V05_AUDIT_MAX_TOKENS=16384。仍须AI_OR_FINALIZER_ENABLED=True及有效通行证/DeepSeek密钥。密钥不得进入Git。新流程目录editor_v05/与旧ai_or_finalizer/隔离，输入/提示hash变化或不确定的付费请求必须人工核对，禁止覆盖旧断点或重复请求。缺少原稿需补充，不重新付费抓取。

前端沿用Word、相似度审查报告和交付包按钮，不修改两处审稿导航入口。旧书原下载路径兼容保留。0.5只表示编辑交付版本，不表示Epic Novel Engine整体验收完成。
