# AI 审稿降率：报告驱动 v5

本文档只描述独立“AI 审稿降率”页面的 `report-driven-v5` 链路。

- 不修改普通生成链路的全局策略。
- 不处理小说、家长里短长篇或 Epic Novel Engine。
- 不重检、不改写、不回填任何历史已完成任务。
- 不声称逆向朱雀内部算法；只做真实报告支持的黑盒差分实验。

## 自动通过标准

候选只有同时满足以下两类条件才能进入 AI 审稿书架“已通过”区域并解锁下载：

1. 候选正文 SHA-256 与复检报告送检正文完全匹配，报告正文抽样匹配通过。
2. 朱雀首页官方人工特征 `>=25%`。`24.99%` 不通过。
3. 首页人工、疑似 AI、AI 三项均被可靠识别，取值范围有效，合计约为 100%。
4. 首页官方值和片段表推导值分别保存；表格推导值永远不能替代官方值解锁终稿。
5. 原稿 claims 100% 为 `preserved`，没有 `altered` 或 `missing`。
6. 候选 `added_claims=[]`，没有新增事实、解释、背景、心理、例子、评价或结论。
7. 语义忠实度 `>=98`、信息完整度 `=100`、流畅度 `>=92`、声音连续性 `>=92`。
8. 数字、日期、金额、专名、引语、书名、URL、否定、限定、因果方向和评价归属完整保留。
9. 没有中、高严重度语言问题；事实类问题无论等级都阻断。

任何一项不满足都进入 `manual_review`。系统保留不可变原稿和最佳安全候选，不把低质量低分稿标记为完成。

## API

- `POST /api/v1/aigc-review/report`
  - 本地提取 PDF 文本或运行本地 OCR，费用 0 元。
  - 同时接收送检原稿，建立片段坐标并验证报告正文匹配。
  - 返回官方/推导双指标、首页可信状态、正文哈希和连续风险区推荐。
- `POST /api/v1/aigc-review/paired-analysis`
  - 接收前后正文及各自真实朱雀 PDF。
  - 用正文坐标、锚点和文本重叠矩阵对齐变化后的片段边界。
  - 输出边界变化、文本特征差分、质量风险和待验证假设。
  - 结果固定为 `learning_eligible=false`，不会把相关性冒充因果。
- `POST /api/v1/aigc-review/optimize`
  - `layout_only`：只重排空白和自然段，非空白正文哈希必须一致，模型费用 0 元。
  - `syntax_constrained`：DeepSeek 基于原稿、上下文和事实账本做最小必要句法编辑。
  - `combined`：在人工确认后组合句法编辑与段落边界重组。
  - `detector_probe`：隔离的朱雀黑盒探索实验。当前 `controlled-v3` 每轮只改一个变量；本轮只在一个 1200–2500 字宏块中替换反复出现的机器化连接标记，事实、段落、数字、专名和引语不变，模型费用 0 元。
  - 单轮只接受最多 12 个连续相邻风险片段。
- `POST /api/v1/aigc-review/compare`
  - 强制核验候选正文哈希。
  - 以首页官方人工特征和既有质量审查共同判定 `strict_pass`。
  - 整稿归一化对齐只作观察，不作为局部因果学习证据。
- `POST /api/v1/aigc-review/calibrations`
  - 登记 350–2500 字、正文精确 SHA-256 的隔离样本。
  - `external_saas` 永远只作观察。
  - 模型候选只有质量闸门已过且真实报告首页可靠时才可作为本地学习证据。

## 固定实验顺序与费用

1. 首先运行 `layout_only`，模型费用 0 元。
2. 未达到 25% 时，由用户选择 `syntax_constrained`；默认只生成一个 DeepSeek 候选。
3. 仍未达到 25% 时，只有用户明确确认才运行 `combined` 并处理下一段连续宏块。
4. 达到 25% 立即停止，不修改其余正文。
5. 默认单轮模型预算上限 `¥0.30`。达到上限、质量不确定或调用故障时停止，不自动烧钱重试。
6. Grok 只保留手动实验能力，不参与默认自动流程。
7. 事实账本由本地确定性代码生成并缓存，模型费用 0 元；Flash-Lite 只审本轮改动单元。

`detector_probe` 不属于上述质量安全顺序。它只在用户明确确认后运行；每轮必须只有一个主要变量，并且在取得该轮真实复检前不得追加下一变量。即使真实复检达到 25%，归档状态也只能是 `detector_probe_hit`，任务保持 `manual_review`，不写 `05_aigc_final.md`。未命中则停止自动追加费用。

旧版 `zhuque-detector-probe-v1` 的“删模板词 + 全文短句化 + 五种语气轮换 + 第一人称阅读反应”组合已经由正确样本 `ZYF1.pdf → WAS改.pdf` 证伪：人工特征 `0% → 0%`，疑似 AI `69.72% → 100%`，AI 特征 `30.28% → 0%`。它只能把红色推成橙色，不能产生绿色人工特征，且新增了重复的“我读到这里时”模板。该组合已退役，不得再次自动调用。

`zhuque-detector-controlled-v2` 的句界分布单变量也已由真实报告 `ZYF2.pdf` 证伪。候选正文 SHA-256 为 `5e7e54360440e91db660e5a33f2e97e6708b1f8f1eab3ceaf7fe7f1889418157`，报告正文匹配置信度为 `97.33%`；首页人工特征仍为 `0%`、疑似 AI `69.72%`、AI 特征 `30.28%`。唯一受影响的片段 12 从 `0.9436` 降到 `0.9315`，但仍为疑似 AI，官方人工占比没有增加。该变量已退役，不得再次作为默认实验。

旧版探索 Prompt 与语气配置仅作为失败实验复现材料保留，不再进入自动流程：

- `backend/app/prompts/aigc_detector_probe.md`
- `backend/app/prompts/aigc_detector_probe_profiles.json`

编辑单元默认 600–900 字，最终按主题形成 1200–2500 字宏块。不得跨标题拼接。推荐单轮处理约占全文 30%–35% 的连续高收益区域；报告边界导致单块过大时保留人工选择。

## 事实账本与质量审查

事实账本默认由本地 `local-deterministic-v2` 按句建立，逐条保存原句位置、否定、限定与保护锚点；它完整且无需模型调用，不会因 JSON 截断或 `MAX_TOKENS` 中断。模型事实提取仅保留为研发对照注入点，任何无效或截断响应都会立即回退本地账本，不进行第二次付费重试。

旧事实账本 Prompt 仅用于研发对照：

- `backend/app/prompts/aigc_report_fact_ledger.md`

每条 claim 必须包含原句位置、限定、否定、模态、评价归属和保护锚点。原句作为终审证据保留，不作为候选稿直接输出。

受限编辑 Prompt 位于：

- `backend/app/prompts/aigc_report_reauthor.md`

编辑模型同时看到原稿、相邻上下文和事实账本。长度必须保持在原编辑单元的 `0.95–1.08`，禁止新增解释、总结、经历、历史知识、心理活动和口号化拔高。字面相似度只作诊断，不再设置“必须不像原稿”的偏离门槛。

质量审查 Prompt 位于：

- `backend/app/prompts/aigc_report_quality_audit.md`

审查模型必须返回每个 `audit_id + claim_id` 的结果。业务代码再次核对返回集合和事实账本是否完全一致；缺少、重复或账本外 claim 都是高严重度失败，不能靠模型自报 `pass=true` 绕过。

终审默认每次只审 1 个 600–900 字单元，并按 claim 数动态分配最多 6000 个输出 token。若终审仍发生 `MAX_TOKENS` 或服务故障，接口返回可重试的 `manual_review`，保留已经生成且通过确定性保护的候选，但绝不把未完整终审的候选交付为通过。

## 前后报告差分

外部 SaaS 样本可能同时改变片段边界、句长、段长、篇幅、事实和文气，因此只能生成候选假设：

- 差分、机制假设、相关性和校准样本只保存在后端研发接口与报告文件中，不在用户前端展示。
- 前端只保留原稿/报告上传、片段选择、处理方式、费用上限、质量结果、真实复检、归档和下载。

- 可隔离验证：同主题自然段重组、句长/段长波动、连接词密度和标点分布变化。
- 必须拒绝：新增事实、删除信息、弱化限定、改变因果、替换立场、口号化结论和无根据拔高。

系统不按前后片段编号直接配对。对齐依据为归一化正文坐标、文本相似度和数字/日期/引语等锚点重叠。`13` 块变 `10` 块仍可建立重叠矩阵，但其因果可信度固定标注为 `observational_confounded`。

本次 `ZYF` 实样交叉验证记录：

- 报告字符数 `14,638 → 13,421`，缩短 `8.31%`；OCR 正文的字符相似度约 `70.19%`，逐句中位相似度约 `68.91%`，证明不是单纯换段。
- 句长变异系数约 `0.4484 → 0.4947`，短句占比约 `16.88% → 26.91%`；这些只构成待隔离验证的节奏假设。
- 报告片段 `13 → 10`，首页人工特征 `0% → 67.64%`；修改稿表格绿色占比为 `59.45%`，直接证明首页值不是绿色片段占比的简单求和，但不能推出其内部公式。
- “将军出城迎接”“危难时需要硬骨头”等表述在原稿已有语义依据，不能误判成新增事实；真正应拒绝的是丢失“不在于……而在于……”的否定、把“劳军”改成“出征”，以及新增“打遍天下无敌手”“一生清白”等绝对化判断。
- 该样本同时改变内容、长度、句法和边界，且质量失败，因此不能证明其中任一变量是朱雀提升的原因，固定不可直接晋升为自动策略。

## 降率证据等级与外部 SaaS 保底

后端必须公开当前用户的 `detector_efficacy.status`，禁止把工程设计冒充实测效果：

- `unproven`：不足 2 个同一策略、精确哈希、质量合格、真实 PDF 的方向一致对照。当前只能称为安全实验平台。
- `directional`：同一策略至少 2 个真实对照均提高首页人工特征；仍不能承诺稳定显著增益。
- `validated`：同一策略至少 5 个真实对照，胜率 `>=80%`，人工特征中位提升 `>=5` 个百分点。

若本系统受控实验没有建立方向性证据，可把外部 AI 橡皮擦稿作为保底输入，但必须遵守：

1. 外部稿及报告只证明外部稿本身，固定 `learning_eligible=false`。
2. 系统只针对 claim 审查明确指出的新增、删减、限定/因果变化和语言硬伤做最小质量修复。
3. 每次质量修复都会产生新正文哈希；外部报告立即失效，必须把修复后的那一版重新送朱雀。
4. 不允许沿用外部稿的 67.64% 等旧结果为修复稿解锁；修复稿自己的首页官方值必须 `>=25%`。
5. 任何修复导致人工特征回落或质量仍失败，都保留外部稿和原稿进入人工复核，不继续自动烧费。

## 审稿书架

每次优化都会建立独立人工复核任务，保存：

- 不可变原稿 `04_format.md`。
- 待复检候选 `05_aigc_candidate.md`。
- 首次和复检报告、质量报告、正文哈希、策略版本、实验类型、模型和费用。

只有比较接口返回 `strict_pass=true` 时才写入 `05_aigc_final.md` 并把任务改为 `completed`。失败时任务保持 `manual_review`，原稿始终可追溯。

## 上线验收

- 专项测试覆盖 24.99/25.00 边界、官方/推导双指标、13→10 对齐、排版非空白哈希、逐 claim 覆盖、新增/删除/限定/因果变化、预算和缓存。
- 后端全量测试和前端生产构建必须通过。
- 部署前后对历史已完成任务与章节计算内容哈希，结果必须零变化。
- 首次灰度只使用新输入：先测 `layout_only`，再测 `syntax_constrained`。只有真实朱雀报告证明有效且质量全过的变化才能进入后续策略库。
