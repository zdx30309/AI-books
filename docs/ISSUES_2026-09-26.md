## 一、安全（最高优先级）

| # | 问题 | 状态 |
|---|---|---|
| 1 | **生产环境没配 `JWT_SECRET`**，一直用仓库里写死的默认密钥签发登录令牌。任何看过代码的人都能伪造任意账号的登录令牌。（确定，已在 ECS 实测） | **本次已修**：ECS 生成随机密钥；代码在生产环境拒绝使用默认密钥。所有用户需要重新登录一次 |
| 2 | **注册开放，登录后可让服务器读取任意文件。** 创建任务时 `config` 里可以直接传 `source_text_path` / `style_notes_path`，worker 照着读，内容还会发给模型、写进书稿。`.env`（全部 API key）因此可被读出。（确定） | **本次已修**：接口入口丢弃这类服务端字段；worker 读文件时只允许 `backend/` 目录 |
| 3 | 客户端还能在 `config` 里注入 `poll_timeout_seconds`、`generation_hold`、`active_run_*`、`paid_call_*` 等内部控制字段，绕过超时或伪造运行状态。（确定） | **本次已修**：同上一起过滤 |
| 4 | **全站只有 HTTP。** Caddyfile 写的是 `http://sheke.asia`，而且 `sheke.asia` 现在没有 DNS 解析，实际是用 IP 访问，密码和登录令牌明文传输。（确定） | **待办**：需要你把域名解析到 101.200.48.238，之后我改 Caddy 自动签 HTTPS |
| 5 | 下载直链把完整的 7 天登录令牌放在 URL 的 `?token=` 里，会进访问日志、浏览器历史和 Referer。（确定） | 待办：改成一次性短时下载票据（前后端都要改） |
| 6 | `/api/v1/system/health` 不需要登录，每次请求都投递一个 Celery 任务并阻塞 6 秒，匿名请求就能打满线程和队列。（确定） | **本次已修**：结果缓存 20 秒，同一时间只探测一次 |
| 7 | 会话记录里泄露了北京 ECS 和日本代理的 root 密码（我上次读配置时的失误）。 | **待办（你来做）**：改这两台机器的密码 |
| 8 | 线上会公开前端完整源码（sourcemap）。 | 上次发布已修 |

## 二、成本与重复付费

| # | 问题 | 状态 |
|---|---|---|
| 10 | **同一条 Celery 消息被重投时会重复付费。** 重投的消息 run_id 不变，而认领只拒绝“不同的 run_id”，于是同一本书会被两个 worker 同时写。触发条件：`acks_late` + 断连、或古文任务跑满 24 小时（超过 visibility_timeout）。（确定，逻辑推导） | **本次已修**：原运行仍在心跳时，重投的消息直接放弃；只有原运行失联才允许接管 |
| 11 | 生产 OpenAI 主笔额度耗尽，一本通用长篇每 5 分钟重试，已失败 306 次。（确定） | **本次处理**：主笔切到 DeepSeek（`deepseek-flash`） |
| 12 | 「重跑失败」只按 1 个名额检查并发上限，却能一次重跑全部失败任务，绕过费用保护；上限是全局计数、先查后插不加锁，并发时会超限。（确定） | 待办 |
| 13 | 选段润色接口直接调付费模型，没有任何限流。（确定） | 待办 |
| 14 | 家族长篇：批量生成失败时把“正文已保留”的章节改成失败，重试会整章重新付费；后台模式的 response_id 只存不用，超时后重试必然重新付费。（确定） | 待办 |
| 15 | 家族长篇的 `LONG_NOVEL_MAX_PROJECT_COST` 预算上限从未生效；Gemini / DeepSeek 用量按字数除 4 估算，中文会低估好几倍。（确定） | 待办 |
